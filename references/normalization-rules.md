# 自动规范化与人工复核

## 目标

把可以唯一确定的转写格式问题自动修正，减少重复确认；把可能改变事实或专业含义的内容继续交给用户判断。

自动修正结果必须写入 `normalization-audit.json`，保留原句、修正句、规则编号和时间范围。

## 可以自动修正

- 中文年份缩写，例如“专利延长到三三年”可确定为 `2033年`。
- 明确的年月日写法，例如“七月二十号”可写为 `7月20日`。
- 连续月份口述，例如“四五六三个月”可写为 `4月至6月`。
- 重复数字或单位，例如“六六成”可确定为 `六成`。
- 标准缩写格式，例如 `PKPD` 可写为 `PK/PD`，`LPA` 在靶点语境中可写为 `Lp(a)`。
- 中文字符间由 VAD 分段引入的空格。

规则只能处理模式明确、上下文无冲突的情况。规则不得猜测药名、机制、比较关系或金额单位。

## 必须人工确认

- 同音医学术语，例如“基械”可能是“基线”“基因”或“机械”。
- 同音药名或药理词，例如“踏兵”应确认是否为“他汀”。
- 监管机构缩写存在多个候选，例如 `CDA`。
- 产品名、项目代号和公司名没有官方来源或用户确认时。
- 同一数字可能对应不同单位、口径或时间范围的。

## 用户修改提案

用户可以只修改 `review-proposal.md` 中对应条目的“建议”行。应用时使用：

```powershell
& "<skill-dir>/scripts/run_mm.ps1" apply-proposal "任务目录/transcript.json" --proposal-md "任务目录/review-proposal.md" --out "任务目录"
```

Markdown 提案按片段 ID 应用，不依赖 `review.json` 中的旧状态。应用后再运行安全规范化并重新生成复核清单。

## 规则扩展

通用规则维护在 `assets/normalization-rules.json`：

- `safe_regex_rules`：可以自动执行的确定性替换，可带上下文条件。
- `ambiguous_terms`：只用于发现和提示，不得自动替换。

新增自动规则前必须回答两个问题：

1. 该写法是否只有一种合理解释？
2. 错误替换是否会改变专业术语、数字口径或事实关系？

任一问题不能确定时，放入 `ambiguous_terms`。
